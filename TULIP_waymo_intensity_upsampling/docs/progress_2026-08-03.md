# TULIP再現・Waymo 32→64ライン研究 進捗（2026-08-03）

## 1. 研究の目的

TULIP（Transformer for Upsampling of LiDAR Point Clouds）のrange imageベースの
LiDAR高解像度化を、Waymo TOP LiDARへ適用する。

本研究で扱う主タスクは次のとおり。

- 入力: 32ラインのrangeとintensity
- 教師: 同一フレームの64ラインrangeとintensity
- 予測対象: 64ラインのうち32ライン入力に存在しない奇数ring
- 下流評価: 清水研究の静的地図・自己位置推定への接続

16ライン系は主タスクに含めず、32→64ラインを中心に進める。

## 2. TULIP論文との対応

原論文は低解像度LiDARをrange imageへ投影し、垂直方向を高解像度化する問題として扱う。
代表的なKITTI設定は16×1024から64×1024への4倍アップサンプリングであり、主な予測対象は
rangeである。

現在の研究は、その考え方を次のWaymo条件へ変更している。

| 項目 | TULIP原論文の代表設定 | 現在のWaymo設定 |
|---|---|---|
| データ | KITTIなど | Waymo Perception v1.4.3 |
| 入力高さ | 16ライン | 32ライン |
| 出力高さ | 64ライン | 64ライン |
| 垂直倍率 | 4倍 | 2倍 |
| 水平幅 | 1024 | 2650 |
| channel | range中心 | range + raw intensity |
| 低解像度生成 | 高解像度から垂直間引き | 64ラインの偶数ringを厳密抽出 |
| split | 論文既定split | Waymo segment単位 |
| 下流用途 | 点群品質・認識評価 | 静的地図・自己位置推定評価 |

したがって、現状はTULIP論文の完全な同条件再現ではなく、TULIPのrange image
upsampling問題をWaymo 32→64とintensity補間へ移植する段階である。

参考:

- Paper: https://openaccess.thecvf.com/content/CVPR2024/html/Yang_TULIP_Transformer_for_Upsampling_of_LiDAR_Point_Clouds_CVPR_2024_paper.html
- arXiv: https://arxiv.org/abs/2312.06733
- Official implementation: https://github.com/ethz-asl/TULIP

## 3. 再現できた範囲

### 3.1 range image教師データ

Waymo TOP LiDARのfirst returnから次を取得できる。

- range_64: [64, 2650]
- intensity_64: [64, 2650]
- valid_mask_64: [64, 2650]
- range_32: [32, 2650]
- intensity_32: [32, 2650]
- valid_mask_32: [32, 2650]

32ラインは64ラインの偶数ring 0,2,...,62から生成する。range、intensity、
valid maskが64ラインの偶数行と完全一致することを保存前とペア生成時に検証する。

これは、TULIP論文における「低解像度range imageから高解像度range imageを予測する」
問題設定のデータ部分に対応する。

### 3.2 引き継ぎ研究とのフレーム対応

清水研究の
/mnt/w/32line/datasets/loftr_gt/manifest_cross_eval_gt_v3.csv
を読み、q_subset、q_seg、q_frame_indexで重複除去した。

結果:

- 元manifest: 16,963行
- 一意な評価フレーム: 881
- 元TFRecord欠損: 0

各フレームについてsegment、frame index、camera JSONのtimestamp、元TFRecordを照合する。
881フレームはlocalization_evaluation専用とし、TULIP学習には使用しない。

### 3.3 学習・検証・テストの分離

Waymo training TFRecordをファイル名から列挙し、清水評価と重なるsegmentを除外した。

結果:

- 発見したsegment: 798
- 清水評価と重複して除外: 1
- 学習候補: 797
- train: 639 segment
- validation: 79 segment
- test: 79 segment

分割はフレーム単位ではなくsegment単位で行い、固定seed 20260730とSHA-256順により
再現可能にした。同一segmentが複数roleへ入ることを禁止している。

### 3.4 小規模学習セットの実抽出

最初の学習確認用として、次の12 segmentから一定間隔で240フレームを抽出した。

- train: 8 segment × 20 frames = 160
- validation: 2 segment × 20 frames = 40
- test: 2 segment × 20 frames = 40
- frame index: 0,10,20,...,190
- 抽出失敗: 0

resume再実行では次を確認した。

- pending_frames: 0
- resume_skipped: 240
- indexed_frames: 240
- failed: 0

### 3.5 role付き32→64ペア

抽出した240フレームすべてについて、次の学習ペアを生成した。

- input_32: [32, 2650, 2]
- target_64: [64, 2650, 2]
- input_valid_mask_32: [32, 2650]
- target_valid_mask_64: [64, 2650]
- observed_target_rows: 0,2,...,62
- generated_target_rows: 1,3,...,63

生成結果:

- selected_frames: 240
- indexed_pairs: 240
- built_pairs: 240
- failed_pairs: 0
- train: 160
- validation: 40
- test: 40

出力indexは
outputs/training_pairs_32_to_64/index.csv
である。

### 3.6 PyTorch Dataset

Waymo32To64Datasetを実装済みである。

返却値:

- input: [2, 32, 2650]
- target: [2, 64, 2650]
- input_mask: [32, 2650]
- target_mask: [64, 2650]
- generated_mask: [64, 2650]

generated_maskは、モデルが新しく生成する奇数ringかつ64ラインGTが有効な画素だけを
Trueにする。dataset_roleは明示指定が必須であり、評価indexをtrainとして要求した場合は
エラーにする。

intensityはrawとlog1pを選択できる。Waymoのmask外intensityに含まれる-1 sentinelは、
log1p時にmask外だけ0へ置換する。有効画素に負値がある場合はエラーにする。

## 4. 実装上の工夫

- segment、frame index、timestampの三点でフレームidentityを検証
- 清水評価segmentを学習から二段階で除外
- TFRecordをsegment単位で1回だけ走査
- TensorFlowとWaymo SDKを実処理開始時までimportしない
- dry-runでTFRecordを開かず実行計画を確認
- max-frames、segment上限で小規模確認が可能
- resume時にNPZ、JSON、role、identityを照合
- 一時ファイルから置換する原子的保存
- failures.csvへフレーム単位のエラーを記録
- intensityの外れ値とmask外sentinelを分離
- handover_shimizuの既存処理とTULIP用前処理を分離

## 6. まだ再現していない範囲

TULIP論文のモデル部分はまだ学習・推論していない。

未着手または未完了:

- 1×4 row-based patch partition
- 水平方向circular padding
- 非正方形window attention
- Swin Transformer U-Net encoder/decoder
- skip connection
- pixel shuffle reconstruction head
- 論文準拠のrange pixel-wise L1 loss
- 1 batch forward
- 少数フレームoverfit
- 240フレーム小規模学習
- range MAE、IoU、Chamfer Distance評価
- 64ライン点群への逆投影
- 清水研究の静的地図生成への接続
- 自己位置推定精度への影響評価

## 7. 次に行うこと

1. train、validation、testのDataset/DataLoaderを1 batchずつ確認する
2. 論文準拠のrange-only入力と研究拡張のrange+intensity入力を分ける
3. 既存TULIPモデルの入力・出力channelとWaymo幅2650への適合を確認する
4. 1 batch forwardを実装する
5. generated_maskを用いたlossを実装する
6. 数フレームでoverfitし、lossが低下することを確認する
7. 240フレームで小規模学習する
8. range-onlyとrange+intensityを比較する
9. 予測64ラインを点群へ戻し、静的地図・自己位置推定へ接続する

## 8. 現在の結論

TULIPの「低解像度LiDAR range imageから高解像度range imageを教師あり学習する」
ためのWaymoデータ基盤は完成した。

一方で、TULIP Transformerそのものの再現はこれからである。現在地点は、
データ対応・split・抽出・ペア・Datasetを検証し終え、モデルforwardへ入る直前である。
