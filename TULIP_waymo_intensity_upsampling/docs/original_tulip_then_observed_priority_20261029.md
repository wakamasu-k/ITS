# 合意した実験順序：通常TULIP画像を先に、観測部分保持方式を後に

ユーザー指定により、通常TULIP復元Bを使った照合モデルの適応を先に検証する。観測部分保持方式はその後に比較する。8ライン実験と領域限定補完は独立した実験として扱う。

## これまでの重みの条件

| 条件 | Retrievalの学習画像 | LoFTR |
| --- | --- | --- |
| 既存A：観測16ライン | 従来の観測32ラインで学習した同じ重みを固定 | 従来の観測32ライン側のStage-1重みを固定 |
| 既存B：通常TULIP 16→32復元 | A/Cと同じ従来重みを固定。B画像による再学習は未確認 | A/Cと同じ従来Stage-1重みを固定 |
| 既存C：観測32ライン | 従来の観測32ラインで学習した重み | 従来Stage-1重み |
| 観測8ライン・固定モデル評価 | 従来重みを固定 | 実行時のprotocolを確認 |
| 観測8ライン・epoch52再学習 | 8ライン画像でRetrievalを80epoch学習、独立374QueryのSoft(5m) R@10で選択 | 接続コードは従来Stage-1固定。8ラインでの再学習ではない |
| 既存の観測部分保持方式 | 従来の観測32ラインRetrieval重みを固定 | 従来Stage-1重みを固定 |

画像条件に対応した再学習がなくても精度を測ることはできる。これまでのA/B/Cは固定重みで入力変更の影響を調べる比較。各入力条件で学習した到達性能と区別する。復元画像を使った再学習が必ず改善するとは仮定しない。

## 第一段階：通常TULIP B

1. TULIPは最初のBに使用した重みを固定する。
   `outputs/waymo_16_to_32_baseline_to_moderate_s0_e20/checkpoint.pth`
2. 学習196segment、検証3ペア374Query、test5ペア507Queryの役割を共通化する。TULIP自身の学習splitとの重複も確認する。
3. 学習・検証用に通常Bの地図、アンカー画像、学習用ずらし画像を生成する。test側には既存B画像がある。観測部分保持の合成を入れない。
4. 通常Bと対応カメラ画像でRetrievalを再学習する。学習データから正規化統計を算出し、validation Soft(5m) R@10でepochを選ぶ。testを重み選択に使わない。
5. 507Query・754DBのRetrievalを評価する。過去B固定重みとの比較は照合モデル適応の効果を調べるもの。
6. 通常BのTop10からLoFTR/PnPへ接続。最初は従来LoFTR固定の基準評価とする。
7. B用LoFTRの再学習にはB画像・深度に対応する幾何GTを作り直し、Stage-1/2を学習する。現環境のv7教師生成器が参照するv6は欠落しており、復旧または検証済み代替実装が必要。

学習・検証用B画像の生成とB用Retrieval再学習は、この順序を合意した時点では未実行。既存のB test結果を「Bで学習し直した結果」と呼ばない。

## 第二段階：観測部分保持方式

1. まず第一段階で選んだ同じRetrieval/LoFTR重みを固定して保持方式へ入力を変更し、採用方式の影響を調べる。
2. 必要なら保持方式の画像でも照合モデルを再学習し、入力条件に適応した別の結果として比較する。
3. 画像と深度・点indexの採用元を一致させる。アンカー位置・カメラ・Query/DB集合は共通にする。

## 必要な数値

- Retrieval：Strict R@1/5/10、Soft 2/5/10m R@10、順位中央値。重み選択の主指標はvalidation Soft5m R@10。
- LoFTR/PnP：対応数、3D対応数、インライア数、PnP成功率、全候補失敗Query数、別シーン選択数。
- 最終位置精度：全507Queryを分母とする1/2/5m以内成功率、誤差を計算できた成功例のXY・回転誤差中央値とp95、中央値の対象数。

TULIPの再学習を検討する実験は、照合モデルの再学習とは別に設計する。通常Bの照合モデル適応と保持方式の効果を同時に変更して一つの原因へ帰属させない。
